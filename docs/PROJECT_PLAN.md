# Scope

**In scope**

- Add exact protocol/hostname patterns for every currently referenced catalog image origin to the existing Next.js `images.remotePatterns` allowlist.
- Add one reusable normalization step at the application product-data boundary for leading/trailing whitespace in product `images` and object-variant `images`, covering both static catalog objects and DB-shaped objects already persisted with bad values.
- Correct the leading-tab typo in the ConceMed static catalog URL so future seed runs do not recreate the defect.
- Add focused regression checks for static-catalog and DB-shaped input, including variant image arrays and preservation of image order and otherwise unchanged values.
- Verify all existing product components that render the shared remote image data are covered by the central fixes, including the originally reported Potent Medical and ConceMed URLs.
- Restart the Next.js process and refresh its product cache during runtime verification because configuration and cached DB transformations are applied at startup/read time.
- Reuse the existing `RequestQuoteModal` for the product hero CTA and lower product-detail CTA.
- Lift quotation-open state to the nearest shared product-detail owner so both CTA locations open one modal instance with the same product/category/partner payload.
- Replace only the hero quotation link-to-contact behavior with an accessible button-triggered modal interaction.
- Cover the hero CTA at desktop and responsive widths because the same product hero control wraps onto smaller layouts.
- Preserve the adjacent phone and office link targets and the existing product-enquiry submission flow.

**Out of scope**

- Downloading or migrating partner-hosted images into the local repository or Cloudinary.
- Reworking product cards, galleries, image styling, CMS schemas, or seed content beyond correcting the confirmed leading-tab typo.
- Adding wildcard hosts, permitting protocols not present in the catalog, or disabling Next.js image optimization.
- Migrating the single HTTP catalog origin (`http://combatcancer.com`) to HTTPS; this fix mirrors the catalog's current exact protocol without changing source data.
- Bulk-mutating or migrating current database records; existing dirty values are made safe at the application read boundary.
- Trimming, reordering, filtering, deduplicating, or otherwise rewriting values outside product and object-variant image URL strings.
- Replacing the obsolete `next lint` package command or changing the shared build/dev workflow outside this image fix.
- Changing the global navigation `Get a Quote` links or other quotation CTAs outside product-detail pages.
- Redesigning the quotation form, changing its fields, validation, success/error messaging, or creating a second modal design.
- Changing `/api/enquiries/product`, database schemas, email handling, or admin enquiry pages.
- Changing the `Call Us` telephone number/target, `Visit Office` map URL/new-tab behavior, product content, or layout styling beyond what the trigger refactor requires.

# Architecture summary

The existing stack remains Next.js 16.1.1, React 18, TypeScript, Radix-based dialog primitives, and the built-in `next/image` optimizer. Milestone 1 keeps origin trust in `images.remotePatterns` and URL hygiene at the product-data boundary. For Milestone 2, `ProductDetailContent` is the narrow shared owner of a single quotation open state and single existing `RequestQuoteModal`; it passes one open callback to `ProductHero` and `ProductCTA`, while the owner supplies the current product/category/partner payload. This avoids two independently stateful modal instances and keeps both triggers behaviorally identical without adding global state, a new API, or a new modal component. The existing stack and modal design are reused, so no stack or product decision is required.

# Risks

- **Wrong state ownership creates duplicate or inconsistent dialogs — Likelihood: Medium; Impact: High.** Rendering a second modal in `ProductHero` could let the hero and lower CTA drift in payload, form state, focus management, or success state. Mitigation: keep one state and one `RequestQuoteModal` in `ProductDetailContent`, with both child CTAs invoking the same callback.
- **Product enquiry context is lost during the refactor — Likelihood: Medium; Impact: High.** A modal that opens but submits a blank or different product ID/category/partner is customer-visible data corruption. Mitigation: derive the payload once from the existing product/category props at the shared owner and verify two distinct product routes end to end.
- **Link-to-button change causes an accessibility or responsive regression — Likelihood: Low; Impact: Medium.** The CTA currently benefits from native link behavior and sits in a wrapping action group. Mitigation: use a semantic button, retain existing responsive classes, and test pointer/keyboard activation, focus restoration, Escape dismissal, and small-width wrapping.
- **Adjacent or global CTAs change unintentionally — Likelihood: Low; Impact: Medium.** Broad search-and-replace could alter the phone, office, or global header navigation behavior. Mitigation: limit the diff to the product-detail shared owner and two product-detail CTA components, and assert unchanged href/target attributes plus unchanged global navigation in QA/review.
- **External image server availability — Likelihood: High; Impact: Medium.** Twelve external origins increase the chance that one provider is slow, unavailable, or blocks optimization requests even after configuration is correct. Mitigation: distinguish upstream fetch failures from deterministic source-validation exceptions and record origin-specific results.
- **Stale configuration or cached product transform — Likelihood: Medium; Impact: Medium.** Next.js may keep the previous allowlist or cached dirty DB result. Mitigation: restart the process and ensure the product cache is rebuilt before runtime verification.
- **Insecure HTTP source — Likelihood: Certain; Impact: Medium.** The catalog currently references `http://combatcancer.com`, which lacks transport encryption and may be blocked in some environments. Mitigation: scope the exception to that exact protocol/hostname, test it separately, and treat an eventual source-data HTTPS migration as follow-up work.
- **Normalizer changes data beyond whitespace — Likelihood: Low; Impact: High.** Filtering, deduplication, or mutation could change which product image is primary or damage unrelated fields. Mitigation: use a pure mapping step and assert array order/cardinality, clean URLs, variants, and non-image fields in focused regression checks.
- **Dirty worktree and shared `.next` process contention — Likelihood: High; Impact: Low for this fix.** The repository contains many pre-existing file-mode changes, and an active dev process can contend with a production build for `.next`. Mitigation: limit edits to the allowlist, shared normalization boundary, static typo, and focused checks; preserve user changes, use bounded verification, and report build contention precisely rather than inferring a compilation result.
